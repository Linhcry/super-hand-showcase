# 工程实现

## 本机工作台与工作进程

工作台管理配置、训练入口、仿真、模型选择和结果查看。FastAPI提供本机API，独立Python进程执行耗时任务，任务目录保存阶段、日志、输出和终态。

训练、仿真、数据生成和设备任务分别管理。启动页面和安装环境不自动连接机器人或打开CAN设备。实际设备任务具有独立的控制归属与反馈处理。

## 配置、快照与来源

配置校验覆盖类型、单位、物理组合和任务预算。源码快照与资源摘要确定任务使用的实现；权重有独立摘要。已有工作区不由初始化器覆盖，新候选保留原配置引用。

实际参数、开发默认值、控制器读回与人工确认分别保存。目标角度和实际角度、网络指标和任务结果、主流程时钟与加载墙钟都有独立字段。

## SDK与硬件适配

| 接口 | 工程关注点 |
|---|---|
| FR5 / FAIRINO SDK | 控制器状态、关节/TCP反馈、工具和负载配置、原生运动接口 |
| USB-CANFD | 设备/通道、上游库版本、反馈订阅、12电机映射与指令编码 |
| RGB-D | 帧新鲜度、实际分辨率、深度与RGB、内外参和目标可见性 |
| 工具与工位 | 手/法兰/笔尖关系、桌面与器具、支撑和释放条件 |

历史现场曾成功只读接通FR5、五指手与D435。这证明了当时设备通信链路，完整握持、连续书写和整轮比赛需要各自运行证据。

## 失败诊断

通信失败、反馈过期、不可达、接触问题、路径超时、墨迹不足和资源不足具有不同诊断路径。自动候选不会通过替换失败场景或更换分母来晋升。

停止、关闭和运行异常分别留证；关闭失败不能留下单纯完成标记。重新启动软件也不代表实际笔、纸和机器人已经恢复初始状态。

## 部署与资源

基准研究环境为Ubuntu x86_64、Python 3.12、MuJoCo和PyTorch，CPU/CUDA依赖分别管理。模型资源下载按固定版本和摘要核对，上游SDK和许可保留来源。

研究目录与现场应用分开部署。内部还维护独立运行与导出流程，公开仓库只展示结构与验证摘要，不提供现场一键执行包。
