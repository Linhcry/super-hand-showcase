# 项目工作与能力映射

Super Hand的工作横跨机器人控制、视觉学习和工程集成。这里按技术问题梳理具体内容，算法组件与实验指标的完整说明在各专题页中展开。

## 1. 把任务拆成可验证的系统

**问题。** 点睛或书写的最终质量同时受工具抓握、目标定位、路径、纸面接触和时间预算影响，单个模型分数不足以解释任务失败。

**方案。** 采用感知、阶段规划、约束求解、接触控制和独立评估的分层架构。每层有明确输入输出，阶段共享工具状态，评估报告分别检查动作完成、机械、墨迹、精度与用时。

**体现的工作。** 跨模块数据结构、状态机设计、任务预算管理，以及从局部模块到完整流程的集成。

**证据。** 系统包含单项训练、完整任务和批次对照入口；历史30场景的成功与失败独立计数。

## 2. 在接触任务中维护工具关系

**问题。** 手指到达目标角度不代表握住工具；继续执行名义闭合还可能造成局部挤压。提笔后，笔尖位置和工具姿态还要保持。

**方案。** 首次接触按手指分别锁存，接触后继续进行法向力反馈。有界姿态维护与握持目标配合，书写控制单独处理笔尖任务。

**体现的工作。** 接触状态建模、Jacobian反馈、执行器范围处理、持握与书写职责划分。

**证据范围。** 这些反馈控制在仿真模块中实现。实际固定布局执行使用经过现场配置的电机位置目标，两条路径不混称为同一种已验证控制。

## 3. 组合视觉学习与几何约束

**问题。** 场景位置变化需要感知适配，而接近、搬运、落笔仍需要满足机器人几何关系。

**方案。** RGB-D分割提供类别和深度线索，经标定反投影形成空间目标；IK使用明确的位姿残差和约束，学习网络只建议初值。目标来源与执行后真值审计分开。

**体现的工作。** 数据生成、网络设计与训练、相机几何、数值求解及输入边界管理。

**证据。** 历史分割模型119,176参数，保存的四类fixture mIoU为0.9150；完整任务另有独立报告。

## 4. 用可解释的学习模块优化任务

**问题。** 将整套行为交给一个策略会增加数据与调试成本，也使局部改进难以归因。

**方案。** 分割、墨迹覆盖、IK初值、剩余时间和局部残差分别学习。单次候选只更新一个模块，保持其余条件，比较完整工作流。

**体现的工作。** 数据与标签设计、监督学习、PPO/GAE实现、模型接口和实验编排。

**取舍。** 模块化有利于复用和诊断；系统仍需解决接口误差传播和跨阶段状态一致性。当前没有证明端到端、任意场景的实机稳定性。

## 5. 把失败转化为可追踪的迭代记录

**问题。** 不同题目、布局或种子下的单次成功容易造成版本比较失真。

**方案。** 固定对照条件，训练前保存候选记录，完整验证后再决定保留。失败报告、未执行数量和原始分母分别保存；候选拒绝后保留此前最佳。

**体现的工作。** 实验可复现性、失败归类、指标设计、版本回退与候选管理。

**证据。** V147历史原30场景14通过、16未通过；3项原有回归失败在整理前后均可重现并被记录。

## 6. 完成算法到本机工程的衔接

**问题。** 算法实验还需要任务进程、模型资源、设备接口、部署环境和可读的操作入口。

**方案。** 本机工作台统一配置与记录；工作进程执行训练或仿真；固定依赖、资源摘要、源码快照和设备适配接口分别管理。

**体现的工作。** Python后端、FastAPI接口、本地前端、进程与资源管理、Linux部署、SDK和CANFD集成。

**证据。** 研究目录在全新位置初始化，5个页面/API返回正常，生成4张合成图并完成1个CPU epoch；离线检查没有打开硬件。

## 项目取舍

| 设计选择 | 获得的能力 | 代价或范围 |
|---|---|---|
| 轻量RGB-D分割 | 本地推理和重新训练成本较低 | 跨光照与真实相机域仍需验证 |
| 学习建议＋约束求解 | 结果可检查，模块可单独对照 | 求解耗时和局部可达性仍需优化 |
| 局部残差PPO | 缩小动作搜索范围 | 依赖可靠基底，未覆盖整轮自主策略 |
| 独立完整任务评估 | 不让局部指标替代最终效果 | 比单项模型评估更耗时 |
| 固定布局应用分支 | 在确定工位复用示教与工具关系 | 布局与安装变化需要重新核对 |
